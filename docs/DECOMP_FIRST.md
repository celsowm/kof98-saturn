# Decompilation-first track (2026-11-19)

Goal (user-directed): turn the KOF98 machine-generated recomp into clean,
readable C **before** further Saturn work, using REA + Ghidra.

## Tooling installed locally (not committed)

- Node.js 26.12.1 and `rea-agents` 6.9.0 CLI.
- Ghidra 12.2 (extracted to a local temp dir) with the native decompiler.
- Temurin JDK 25 (REA requires JDK 25+; Ghidra 12.x).

REA's Windows Ghidra provider refuses raw `m68k` binaries (`target_format_unsupported`:
"Windows Ghidra P0 accepts native PE, DOS MZ, and explicitly selected raw 6502
targets only"), even though REA's general spec lists m68k. So the decompilation
runs through Ghidra headless directly; REA remains available for other targets.

## Local flow

1. `tools/make_flat68k_image.py` builds `local/decomp/kof98_flat.bin`: P1 at
   `$000000`, P2 banks at `$200000`, BIOS (byte-swapped) at `$C00000`, image base 0.
2. `tools/routine_addresses.py` converts the 94-name pruned working set into
   guest addresses.
3. `tools/run_ghidra_decomp.ps1` + `tools/GhidraDecompile.java` import the raw
   image as `68000:BE:32:default`, seed functions at requested addresses, and
   export C-like pseudocode.

All ROM-derived inputs and outputs live under ignored `local/`.

## Measured result

- BIOS routine `$C11002` (the BIOS block that copies the 68000 routine into
  work RAM) decompiles cleanly: a memcpy-style loop with named temporaries.
- The 94-routine boot working set: 91/94 decompiled, 135 KB of pseudocode. Three
  addresses gave no function (`000800`, `C00402`, `100000` — the last is WRAM,
  not present in the flat ROM image).
- Many game routines truncate with `/* WARNING: Bad instruction - Truncating
  control flow here */`. Cause: the flat image has no WRAM/I/O/banked-RAM
  regions, and the guest code jumps through those; Ghidra cannot follow them.
  The existing machine-generated recomp C remains the more complete translation
  of the code.

## Machine-cleaned C (first deliverable)

`tools/clean_ghidra_c.py` turns the pseudocode into ordinary, typed C:
standard `stdint.h` types, address-bearing names (`wram_fn_100000`,
`wram_mem_0010fce8`), section markers as comments, deduplicated bodies,
Ghidra `CONCATxx`/`DAT_`/`FUN_`/`code` idioms normalised, and a companion
header declaring every global/function. Both outputs pass a host GCC
`-fsyntax-only` check:

| source | output | defined functions | bytes | truncations |
|---|---|---|---|---|
| 92 WRAM dispatch entries (WRAM mapped into the flat image) | `local/decomp/wram92_clean.c` | 65 | 75,367 | 1 |
| 81 boot routines (from the corrected full dump) | `local/decomp/hot94_clean.c` | 53 | 58,538 | 0 |
| 925 executed routine entries (top-500 per profile + WRAM + boot) | `local/decomp/all_exec_clean.c` | 480 | 922,695 | 1 |
| **3,726 all-profiled routine entries** (union of all saved profiles) | `local/decomp/all_profile_clean.c` | **2,097** | **4,590,686** | 24 |

Mapping the live WRAM dump at `$100000` made **92/92** WRAM routines decompile
with zero failures; the Ghidra output is readable loop/branch C (e.g.
`$100000` initialises a structure then loops calling `$1008a6` and `$10079e`).
This is the concrete "pure C" starting point: compilable translation units with
stable names, ready for semantic naming and typing by hand or agent.

## Correcting the decompiler image (byte order)

Most game routines initially truncated with `Bad instruction - Truncating
control flow here`. Root cause: **all three program images (P1, P2 and BIOS)
are stored byte-swapped** in the local ROM dumps. The old image swapped only the
BIOS. After `tools/make_flat68k_image.py` swaps P1/P2 too, the reset vector at
`$000000` decodes correctly as SSP `$0010F300` / PC `$00C00402` (the known BIOS
boot path), and P1/P2 routines decode as real 68000 instructions (e.g. `$122`
is `JMP $00009C14`). Decompilation is re-run from the corrected image.

## Conclusion gate

`tools/finalize_pure_c.py` is the single reproducible final step: it cleans the
Ghidra dumps into C11 with explicit casts for every Ghidra loose
pointer/integer assignment, compiles every translation unit with
`tools/verify_pure_c.py` (no error suppression: `-Werror=implicit-function-declaration`,
`-Werror=incompatible-pointer-types`, `-Werror=int-conversion`), and writes
`local/decomp/pure_c_manifest.json`. `tests/test_clean_ghidra_c.py` is a ROM-free
regression for the cleaner and is registered as ctest `clean_ghidra_c`.

The address seed (`local/decomp/all_exec_addrs.txt`) is the union of the top 500
routines by instruction count from each saved native profile plus the 92 WRAM
dispatch entries and 94 boot routines. It covers **99.87%** of executed
instructions in `fight.csv`, **100%** in `noinput1200.csv` and **99.74%** in
`playlong.csv`.

Final measured gate (`local/decomp/pure_c_manifest.json`, regenerated by
`python tools/finalize_pure_c.py`):

```
CONCLUSION: PASS
verify: wram92_clean.c OK / hot94_clean.c OK / all_exec_clean.c OK /
        all_profile_clean.c OK
```

Coverage was widened from the 925 top-routines seed to the union of **every**
routine address in the three saved native profiles (`tools/make_all_profile_addrs.py`):
3,726 entries, 2,097 unique function bodies, 4.59 MB of compilable C11.
`all_profile_clean.c` compiles with plain `gcc -std=c11` and no error suppression.

Before the byte-order fix the 925-routine set had **852 truncated bodies**; after
it, **1**. Every cleaned translation unit compiles with plain `gcc -std=c11`
and no error suppression, and the 40/40 ROM-free host tests pass (including the
new `clean_ghidra_c` regression).

All cleaned C, ROM inputs and manifests stay under ignored `local/`.

## Remaining scope (not claimed as done)

The generated C is compilable and address-named, not semantically renamed.
A full game port would still need: semantic names/types for the `*_mem_*`
globals, full coverage of the 40,801 routines / 57,972 dispatch entries (the
3,726 profiled entries cover captured runs, not the whole game), and a
checkpoint-driven equivalence harness for cleaned routines (the existing
`ng_recomp_host` compares machine recomp vs Musashi, not Ghidra C). An attempt
at a differential cleaned-C vs recomp-C driver was started but not completed,
so it is deliberately not committed. No Saturn build changes were made in
this track.
