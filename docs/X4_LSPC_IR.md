# X4 — scanline LSPC render IR

Initial portable semantic reference, based on the pinned NeoGeoRecomp video.c (a47ee3fe09dc46d1f2b86c36ec972b43b35ebf62). This is NOT a Saturn renderer or a claim of hardware-equivalent Neo Geo emulation. Scope: original 320x224, no widescreen copies.

Consume guest-endian-decoded VRAM words and the exact local 64 KiB L0 zoom ROM at each visible scanline, with the current autoanimation counter and FIX source. Evaluate 381 columns in ascending order, at most 96 active columns per scanline (offscreen columns still consume the evaluation budget, matching the pinned oracle). Preserve sticky X advance with previous width, inherited vertical control, 512 wrap, heights 33+ repeating vertically, inversion, the 16 exact horizontal shrink masks, ROM row selection, flip, autoanimation priority, and 19-bit tile address masking for KOF98. Clip to 320 columns. Each emitted span includes slot/order, absolute tile ID, source row, logical pre-flip pixel mask, screen x/width and palette index. FIX spans preserve 40 columns with tile, palette and row; compose after sprites. Backdrop and palette bank/contents remain caller-owned raster state. No RGB palette state or snapshot serialized yet. Caller must not use stale palette contents for raster changes.

The reference converts Neo Geo palette components to Saturn RGB555 (MSB set, R low bits), losing the dark-bit DAC distinction. Both dark variants intentionally map to the same five-bit channel codes; pen zero must be set to zero separately for transparency, not passed through the RGB converter. Pen 15 remains a normal color; target VDP1 must disable end-code interpretation. Actual SDK output must be checked. FIX 8x8 graphics are already repacked by pack_tiles.py but not uploaded to VDP2.

## Evidence

Compiled the portable core and differential test with cc -std=c11 -O2 -Wall -Wextra -Wpedantic -Werror; passed. Also compiled and ran with AddressSanitizer and UndefinedBehaviorSanitizer; passed. Eight synthetic VRAM snapshots, pseudo-random zoom table, 224 lines each: 1,792 scanlines / 573,440 pixel positions compared with a separate scalar reference using a rank permutation for shrink. The synthetic pixel function includes transparency and sprite overlap. Checked evaluated-column count, clipped extent, ordering, FIX addressing and all 65,536 input color words. This is not a comparison against a game capture, real L0 ROM, or the pinned upstream binary; both implementations derive their behavior from the inspected oracle. FIX compositing and palette raster fidelity are not tested. CTest registration added but full repository suite and CI not run here.

## Integration gate

Do not emit one VDP1 command per span: worst-case 96 * 224 = 21,504 sprite spans per frame before FIX. That exceeds practical command budgets. Keep streaming one line as a host/reference model. Build trace capture at actual raster timing, then coalesce across lines only when tile, source mask/rows, positions, flip, order and palette content are compatible. Prefer native 16x16 full-zoom tile commands where they match; use pre-shrunk patterns/strips for exact zoom rather than assuming Saturn sampling matches. If a region cannot be represented exactly, report unsupported or use a proven fallback; do not silently drop spans. Evaluate VDP2 candidates separately with correct priority and raster semantics. Measure simultaneous unique tiles/LUTs and command counts against X4 cache limits. Before target use, verify pen 0/15, LUT byte order, clipping, draw fences, palette changes and actual framebuffer on Ymir/hardware.

No game ROMs, target toolchain or emulator available here. This is the portable IR and color conversion, not yet connected to upstream video_render_line or VDP1. No ROM-derived data committed.
